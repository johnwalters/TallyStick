# Accounting Application TODOs

**Status:** All follow-up items in this tracker are complete as of August 24, 2026. New product features should be recorded in a new feature specification and tracker.

Follow-up requests explicitly added during implementation sessions. These are separate from the original MVP task baseline in [tasks.md](tasks.md).

Use `[ ]` for an open TODO and `[x]` only after the behavior is implemented and verified.

- [x] **TODO-001** *(requested as P5-002a)* Make the all-accounts transaction view read-only. When no financial-account card is selected, disable statement import and every transaction mutation control, including row/select-all checkboxes, category selection, posting, matching, excluding, undoing, deleting, and all bulk actions. Continue allowing read-only filtering, sorting, and reporting, but require one explicit account selection before any operation that could affect transactions so actions never span accounts. **Evidence:** UI controls are disabled and service methods guard against mutation without an explicit account; the fixture-driven UI test covers the all-accounts state.
- [x] **TODO-002** *(requested as P5-008c)* When an assigned category is truncated in a transaction row, display the complete category text while the user hovers over it so the full category can be read without changing the table layout. **Evidence:** Pending and posted category elements expose the complete category path through an explicit in-app hover tooltip (with a native `title` fallback); the category-picker UI test asserts the full path.
- [x] **TODO-003** *(requested as P5-022b)* Rename the bulk Excluded-state deletion button to **Delete All** and give it the same visual style as the other transaction-toolbar buttons; retain the destructive-action confirmation. **Evidence:** The Excluded toolbar renders `Delete All` with the standard `quiet-button` class and the UI test verifies the label/style; the existing confirmation remains in `deleteSelectedExcluded()`.
- [x] **TODO-004** Fix clearing an assigned category from a Pending transaction. Choosing **Clear category** must remove the Pending transaction's category immediately and persist the cleared state when the view is reloaded, the account is changed, or the application is restarted. **Evidence:** Clearing records an audited `CLEARED` categorization source, suppresses category-rule/prior-match suggestions while retaining transfer matching, and survives account changes, component recreation, and SQLite export/reopen.
- [x] **TODO-005** Default the P/L report to **Year** grouping when the Reports workspace is first opened, while continuing to let the user select Month grouping. **Evidence:** the component and initial P/L report both initialize to `YEAR`; the monthly subtotal/drill-down regression explicitly selects Month and continues to pass.
- [x] **TODO-006** Allow the transaction-list search field to match formatted and unformatted transaction amounts, including positive, negative, decimal, and currency-formatted input. **Evidence:** service tests cover `$40.00`, `+40.00`, `-13.00`, `-$13.00`, `1,234.56`, and `-$1,234.56`; the register search placeholder now includes amount.
- [x] **TODO-007** Remove confirmation prompts from transaction posting. Both the row-level **Post** action and the bulk **Post selected** action should post immediately when their existing validation requirements are satisfied. **Evidence:** row and bulk UI regressions assert `window.confirm` is not called; uncategorized selected rows still remain Pending.
- [x] **TODO-008** Change the import-section heading from **Bring in a statement or Amazon summary** to **Upload file**. **Evidence:** the rendered shell regression asserts the exact `Upload file` heading.
